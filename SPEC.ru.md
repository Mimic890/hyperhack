# hyperhack — спецификация проекта

Английская версия (основная): [SPEC.md](SPEC.md). Оба файла держать одинаковыми.

Название: `hyperhack`.
Лёгкая замена Ghost. Ghost слишком тяжёлый для одного автора.

## Цель

Лёгкий и быстрый блог одного автора.
Посты — Markdown-файлы в S3.
Автор пишет в Obsidian и публикует синхронизацией vault с бакетом.

## Объём

### В MVP

- Главная страница.
- Страницы постов, рендер из Markdown.
- Поиск по постам.
- Списки «Новые» и «Популярные».
- Метрики поста: просмотры (публично), время на странице (только метрика).
- Расчётное время чтения на каждом посте.
- Анонимные лайки и дизлайки.
- RSS-лента.
- Интерфейс на английском и русском. Язык по умолчанию из `.env`, переключатель для читателя в верхнем баре.
- Эндпоинт `/metrics` и дашборд Grafana.
- Структурированное логирование с уровнями.

### Вне объёма

- Несколько пользователей, регистрация, роли.
- Веб-редактор и админ-панель для постов.
- WebDAV. Хранилище только S3.
- Общая аналитика трафика. Её дают логи reverse proxy и Grafana.
- Перенос старых постов из Ghost.

## Решения

| Область | Решение |
|---|---|
| Пользователи | Один автор. Регистрации нет. Публичная часть только читает. |
| Backend | Go 1.27, последняя стабильная (go1.27.3 на 2026-11-03). `go.mod`: `go 1.27` + `toolchain go1.27.3`. Образ сборки: `golang:1.27`. Перед стартом проверить go.dev/dl; дальше версию обновляет Dependabot. |
| Frontend | Серверный рендер через `html/template`. Без фреймворка. Минимум vanilla JS: голоса, ALTCHA, beacon просмотров и времени, палитра поиска, оглавление, кнопки копирования и «Поделиться», переходы между постами, диаграммы Mermaid (Pele). |
| Темы | Светлая и тёмная, переключатель в верхнем баре. По умолчанию тема системы, пока читатель не выбрал свою. Выбор хранится в cookie и рендерится на сервере (без inline JS). Переключатель — форма, которая отправляет `/prefs`, поэтому работает без JS. |
| Дизайн | См. Дизайн. Шрифты: Onest (текст) и JetBrains Mono (код и маркеры заголовков), OFL, свои, наборы латиница + кириллица. |
| Языки | Код, доки, интерфейс — английский. Интерфейс также на русском. По умолчанию — `DEFAULT_LANG` (`en` / `ru`) в `.env`. Выпадающее меню для читателя в верхнем баре; выбор хранится в cookie (сервер должен знать язык для рендера). Текст постов не переводится. |
| Хранилище | Garage (S3 API), path-style адресация. Клиент: `github.com/minio/minio-go/v7`. |
| Формат поста | Один `.md` = один пост. Метаданные — свойства Obsidian (YAML frontmatter). |
| Метрики | Формат Prometheus на `/metrics`, сбор через VictoriaMetrics, дашборд Grafana. |
| Логи | `log/slog`, уровни DEBUG / INFO / WARN / ERROR. |
| Развёртывание | Docker + Docker Compose. Образ собирает GitHub Actions. |
| Репозиторий | Публичный, GitHub. Лицензия AGPL-3.0 (автор добавит при создании репозитория). |

## Дизайн

Относится ко всем страницам. Страницы работают без JS; JS только улучшает их.

### Цвета

CSS custom properties. Механизм тем не меняется: `prefers-color-scheme`, cookie, `data-theme`.

| Токен | Тёмная | Светлая | Роль |
|---|---|---|---|
| `--bg` | `#0A0A0A` | `#FFFFFF` | фон страницы |
| `--raise` | `#171717` | `#F5F5F5` | карточки, код, меню |
| `--line` | `#262626` | `#E5E5E5` | границы, разделители |
| `--text` | `#EDEDED` | `#171717` | основной текст |
| `--muted` | `#A3A3A3` | `#5C5C5C` | мета, подписи |
| `--uv` | `#3B82F6` | `#2563EB` | акцент: ссылки, `#`, активные состояния |
| `--ember` | `#3B82F6` | `#2563EB` | второй акцент: «Новый пост», конец градиента; по умолчанию тот же синий |
| `--uv-soft` | `rgba(59,130,246,.14)` | `rgba(37,99,235,.10)` | фон активных элементов |

- Градиент `--uv` → `--ember` есть только в полосе прогресса чтения.
- Контраст текста не ниже 4.5:1, проверяется в тесте.
- Текст на `--uv-soft` всегда `--text`. Там `--uv` только у иконок и границ.
- Текст цвета `--ember` только на `--raise` или `--bg`: эти пары проверяет тест контраста.

#### Свои цвета

Владелец может поменять любой токен в каждой теме: `theme` в `home.md` для всего сайта, `theme` во frontmatter поста для страницы этого поста.

```yaml
theme:
  light:
    background: "#F6F5FB"
    text: "#1B1930"
    accent: "#5B3DE6"
  dark:
    background: "#101119"
    accent-soft: "#8B6CFF24"
```

- Имена: `background` (`--bg`), `surface` (`--raise`), `border` (`--line`), `text` (`--text`), `muted` (`--muted`), `accent` (`--uv`), `accent-2` (`--ember`), `accent-soft` (`--uv-soft`).
- Значение: hex-цвет `#rgb`, `#rgba`, `#rrggbb` или `#rrggbbaa`; последние две цифры — прозрачность, она нужна `accent-soft`. `#` можно не писать. Цвет с `#` берётся в кавычки: в YAML `#` без кавычек начинает комментарий, и сервис об этом предупреждает.
- Любой цвет можно не указывать, пустое значение — это отсутствие цвета. Цвет поста важнее цвета из `home.md`, а тот важнее встроенного.
- Неизвестное имя, неверное значение или ключ не `light` / `dark` → пропускается только эта запись, WARN; пост всё равно публикуется. В CSS попадает только проверенный hex-цвет.
- Сервис собирает по таблице стилей на каждый набор цветов, с именем по хешу содержимого, и подключает её после `style.css`: `/static/theme/<hash>.css`. Инлайн-стилей нет, CSP не меняется.
- Контраст своих цветов — выбор владельца, он не проверяется. Подсветка кода сохраняет свою палитру.

### Типографика

- Текст: Onest (OFL, латиница + кириллица), variable `woff2`, начертание normal, свой, в `static/fonts/` вместе с `OFL-Onest.txt`.
- JetBrains Mono только для кода и маркеров заголовков.
- Body 17px / 1.65, текст поста 18px / 1.72.
- Заголовок поста 54px / 1.05 / 800, letter-spacing −0.04em; 34px при ≤ 640px.
- В посте h2 29px / 750, h3 22px / 700.
- Никакого капса в подписях. Метаданные разделяются через `gap`, а не символом `·`.

### Форма и размеры

- Радиусы: карточки 20px, код и callout 14px, кнопки 12px, чипы `999px`.
- Минимальная цель для касания 44px.
- Контейнер `max-width: 1180px`, боковые поля 32px (16px при ≤ 640px).

### Движение

Всё внутри `@media (prefers-reduced-motion: no-preference)`. Новые функции CSS идут через `@supports`; без них страница всё равно выглядит правильно.

1. Список → пост: `@view-transition { navigation: auto; }` на всех страницах. У заголовка и обложки общий `view-transition-name` из slug между списком и постом, 280ms. CSP запрещает inline-стили, поэтому имена через CSSOM ставит небольшой скрипт в `pageswap` и `pagereveal`. Он блокирующий в `<head>`, с `<link rel="expect" href="#main" blocking="render">`, потому что `pagereveal` срабатывает до первого кадра. Элементы вне окна имени не получают. Без JS или этих событий переход между страницами обычный.
2. Прогресс чтения на страницах постов: полоса 2px внизу верхнего бара, градиент `--uv` → `--ember`, `animation-timeline: scroll(root)`.
3. Палитра поиска: фон 120ms, окно из `scale(.98)` и `opacity: 0` за 160ms.
4. Лайк: `scale(.94)` при нажатии, число при изменении сдвигается снизу вверх.
5. Меню языка: появление за 120ms.
6. Название поста в верхней панели: появляется и исчезает за 160ms.
7. Боковое оглавление: одна полоса `--uv` переезжает к активному пункту за 320ms. Передний край идёт первым, задний на 90ms позже, поэтому в пути полоса растягивается и на месте сжимается до высоты пункта. `top` и `bottom` ставит `post.js` через CSSOM. При reduced motion она перескакивает сразу.

Других анимаций при загрузке и при наведении на карточки нет.

### Адаптивность и доступность

- Проверяются ширины 375, 768, 1280 и 1440.
- Видимый `:focus-visible` у всех интерактивных элементов.
- Иконки без текста с `aria-label`.
- `aria-current`, `aria-expanded` и `aria-pressed` везде, где есть состояние.

## Страницы

### Верхний бар

- На всех страницах. Высота 60px, `position: sticky`, фон `--bg` 82% с `backdrop-filter: blur(12px)`, нижняя граница `--line`.
- Слева: лого в рамке 40×29px (`object-fit: contain`), затем название сайта 21px / 750. При ≤ 640px название скрыто и остаётся в `aria-label` ссылки, чтобы бар помещался в одну строку.
- На страницах постов при ≥ 1000px: название поста посередине панели, 13px `--muted`, по центру, не больше двух строк (`line-clamp: 2`), шириной до 36rem. Появляется (плавно, 160 мс) только когда заголовок страницы ушёл под панель, чтобы два заголовка не были видны одновременно; `post.js` следит за `h1` через `IntersectionObserver`. Без JS скрыто. Ниже 1000px названия в панели нет.
- Справа, слева направо: кнопка поиска, переключатель темы, ссылка на RSS, ссылка на GitHub автора (URL из `.env`), последним выпадающее меню языка (`en` / `ru`).
- Кнопка поиска: на главной кнопка в виде поля «Поиск по постам» с подсказкой `Ctrl K`, ширина ≥ 220px, высота 36px. На других страницах и при ≤ 640px только иконка. Без JS это ссылка на `/search`.
- Выпадающее меню языка: кнопка `RU ▾` без рамки, меню на `--raise`, радиус 14px, тень, активный язык цветом `--uv`.

### Главная

Собирается из блоков, перечисленных в `home.md`, файле в корне vault. Имя зарезервировано: этот файл не пост и не попадает в индекс, поиск, RSS, sitemap, `/llms.txt` и `/posts/<slug>.md`. `home.md` в подпапке — обычный кандидат в посты. В имени нет `_`, потому что Remotely Save не синхронизирует такие файлы.

В файле только YAML frontmatter со списком `blocks` и необязательным `theme` (см. Дизайн → Цвета → Свои цвета); тело игнорируется. Блоки идут сверху вниз в порядке файла. Файл перечитывается при синхронизации, как посты.

```yaml
---
blocks:
  - type: intro
    title: Длинные посты про self-hosting и Go.
    text: Заметки о том, как я держу свою инфраструктуру.
  - type: tags
    limit: 6
  - type: featured
  - type: posts
    group: year
  - type: popular
    limit: 4
    area: side
---
```

| `type` | Поля | Что показывает |
|---|---|---|
| `intro` | `title`, `text` (оба необязательны) | Заголовок 46px / 800 и подзаголовок `--muted`, ширина ≤ 720px. Без обоих полей ничего не выводит. |
| `tags` | `limit` (1–20, по умолчанию 6) | Чип «Все посты» и самые частые теги: по числу опубликованных постов, при равенстве по имени. В чипе `#` цветом `--uv`, имя, число постов `--muted`. |
| `featured` | нет | Последний пост. Карточка на `--raise` с рамкой `--line`, радиус 20px, padding 20px. Слева обложка на 1/4 ширины (`4/3`, радиус 14px). Справа «Новый пост» цветом `--ember`, заголовок 30px, описание, дата, время чтения, теги. Нет обложки — текст на всю ширину. |
| `posts` | `group: year \| none` (по умолчанию `none`), `limit` (1–100, по умолчанию `PAGE_SIZE`) | Список постов с пагинацией. Строка: дата слева (92px), заголовок 21px / 650 с описанием `--muted`, время чтения справа. С `year`: заголовки годов 40px / 800 с числом постов года в этом списке словами («5 posts»; по-русски «1 пост / 2 поста / 5 постов») и даты без года. |
| `popular` | `limit` (1–10, по умолчанию 4) | Нумерованный список (1, 2, 3…). Под каждым заголовком: значок глаза с просмотрами за окно `POPULAR_DAYS`, затем значки лайка и дизлайка с текущим числом голосов; значки размером с текст, между просмотрами и голосами отступ шире. У каждого значка визуально скрытая подпись. Без ссылки на RSS: она есть в верхней панели. |

- `area: main | side` у любого блока, по умолчанию `main`. `side` — правая колонка 300px при ≥ 860px; ниже боковые блоки идут после основных.
- Текстовые поля — строка или карта по языкам: `title: {ru: "…", en: "…"}`. Ключи языков — две строчные буквы. Нет записи для языка интерфейса — берётся первая в файле.
- Только plain text, экранируется шаблоном. `title` ≤ 200 символов, `text` ≤ 500. Не более 20 блоков; остальные игнорируются с WARN.
- Нет `home.md`, ошибка в YAML, нет `blocks` или ни один не прошёл проверку → набор по умолчанию: пример выше без текста `intro`, и WARN.
- Неизвестный или отсутствующий `type` → блок пропускается, WARN. Неверное или неизвестное поле → пропускается только это поле, WARN; остальные поля и значения по умолчанию у блока остаются, поэтому `intro` сохраняет заголовок, когда сломан `text`. Пустое значение, в том числе у одного языка в карте, — это отсутствие текста. Число или `true`/`false` берётся как текст.
- WARN повторяются только при изменении файла, а не при каждом опросе.
- Используется только первый блок `posts`, потому что пагинация на странице одна; остальные пропускаются с WARN.
- Пост из `featured` не повторяется в `posts` ни на какой странице.
- На странице 2+ только блок `posts` и пагинация. Без блока `posts` `/?page=2` даёт `404`.
- Один `h1` на странице: заголовок `intro`, иначе название сайта, скрытое визуально.

### Пост

- Рендер Markdown из S3.
- Баннер: обложка (`cover`) над заголовком на всю ширину окна, высота `min(48vh, 460px)`, 260px при ≤ 640px, `object-fit: cover`, без скруглений. Нижняя часть плавно уходит в `--bg`: градиент `transparent 30%` → `--bg 100%` поверх картинки и `backdrop-filter: blur(14px)` под маской `linear-gradient(to bottom, transparent, #000 70%)` в нижних 45%. У `<img>` сохраняются `width`/`height`. Без обложки баннера нет.
- Шапка поста: выровнена по левому краю колонки текста, заходит на баннер на 150px (100px при < 1000px); без баннера не заходит. Порядок: теги, заголовок, мета (дата, `updated`, если задан, время чтения, просмотры). Над баннером мета цветом `--text`, а у заголовка ореол цвета `--bg` (`text-shadow`), чтобы они читались на любой обложке.
- Сетка: текст (`max-width: 680px`) слева, оглавление 250px справа, промежуток 80px. Ниже 1000px оглавление уходит в `<details>` «Содержание» над текстом.
- Оглавление: строится на сервере из h2–h4, у них уже есть id. Дерево: h3 с отступом 30px, h4 46px и мельче шрифт. Слева у каждого пункта линия 2px `--line`. Активный пункт: `--text`, линия `--uv`, вес 600; его родитель h2 тоже `--text`. В боковой колонке линия `--uv` — одна переезжающая полоса (см. «Движение»). Колонка `position: sticky; top: 84px`. Активный пункт отмечает `post.js`: последний заголовок, дошедший до верхней панели (+32px), куда его ставит ссылка из оглавления; в конце страницы — последний видимый заголовок. Нажатый пункт остаётся активным, пока читатель сам не прокрутит (колесо, касание, клавиша), чтобы короткий раздел не отдавал подсветку следующему заголовку. Нет заголовков — нет оглавления.
- Маркеры заголовков: слева от h2 на поле висит `##`, от h3 — `###`. CSS `::before`, не текст; JetBrains Mono, `--uv`, прозрачность 0.6 и 0.45. При наведении ярче; клик копирует ссылку на раздел (JS). Ниже 1000px маркеров нет.
- Блоки кода и callout: см. Функции контента.
- Подвал поста: «Пост был полезен?», лайк, дизлайк. Справа «Поделиться» кнопкой-иконкой 44px (три связанные точки, подпись в `aria-label` и `title`): `navigator.share()` с заголовком и URL, если есть, иначе копирует URL, и иконка на 1,5 с меняется на галочку цвета `--text`; «Ссылка скопирована» уходит только в скрытый визуально `role="status"`. Без JS кнопки нет. Ниже две карточки: «Предыдущий пост» (следующий более старый, если есть) и «Все посты». Карточки: минимальная высота 64px, padding 12px 18px, радиус 16px, заголовок не больше двух строк. При ≤ 640px вопрос стоит отдельной строкой, кнопки и «Поделиться» — следующей.

## Конфигурация

Все настройки и секреты — переменные окружения (`.env`).
В репозитории только `.env.example`. Реальные значения в репозиторий не попадают.

Предложенные переменные (точные имена — при реализации):

| Переменная | Назначение |
|---|---|
| `SITE_NAME`, `SITE_URL` | Название и публичный URL сайта. |
| `AUTHOR_NAME` | Необязательно. Автор в JSON-LD и RSS. По умолчанию: `SITE_NAME`. |
| `DEFAULT_LANG` | Язык интерфейса и язык поста по умолчанию: `en` или `ru`. По умолчанию `en`. |
| `GITHUB_URL` | Ссылка в верхнем баре. |
| `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Доступ к бакету. `S3_ENDPOINT` только `https://`. `S3_REGION` по умолчанию: `garage`. |
| `POLL_INTERVAL` | Интервал опроса бакета. По умолчанию: `60s`, диапазон 10 с – 24 ч. |
| `REINDEX_TOKEN` | Токен для `POST /reindex`. |
| `ALTCHA_HMAC_KEY` | Секрет ALTCHA. |
| `READING_WPM` | Слов в минуту для расчётного времени чтения. По умолчанию: `200`. |
| `LOG_LEVEL`, `LOG_FORMAT` | Уровень и формат логов (`json` / `text`). По умолчанию: `info`, `json`. |
| `DATA_DIR` | Папка для SQLite (`hyperhack.db`). По умолчанию: `/data`. |
| `VAULT_DIR` | Папка для локального зеркала бакета. По умолчанию: `/vault`. |
| `RATE_LIMIT_VOTE`, `RATE_LIMIT_BEACON`, `RATE_LIMIT_REINDEX` | Лимиты на клиента для эндпоинтов записи. По умолчанию: `10/1m`, `30/1m`, `5/1m`. |
| `POPULAR_DAYS` | Окно «Популярных». По умолчанию: `30`. Размер списка — `limit` блока `popular`. |
| `PAGE_SIZE` | Постов на страницу в блоке `posts` (если не задан его `limit`) и на страницах тегов. По умолчанию: `10`. |
| `RSS_LIMIT` | Постов в RSS. По умолчанию: `20`. |
| `DEFAULT_OG_IMAGE` | Необязательно. Картинка превью для страниц и постов без `cover`: файл внутри `assets/`, правила как у `cover`. |
| `INDEXNOW_KEY` | Необязательно. Включает пинги IndexNow. 8–128 символов `a-z A-Z 0-9 -`. Отдаётся на `/<INDEXNOW_KEY>.txt`. |
| `RATE_LIMIT_SEARCH` | Лимит поиска на клиента. По умолчанию: `30/1m`. |
| `VISITOR_SECRET` | HMAC-ключ для суточного хеша посетителя, ≥ 32 байт. |
| `ALTCHA_EXPIRES`, `ALTCHA_MAX_NUMBER` | Срок жизни и сложность задачи. По умолчанию: `5m`, `100000`. |
| `METRICS_ALLOW`, `REINDEX_ALLOW` | CIDR, с которых можно вызывать `/metrics` и `/reindex`. По умолчанию: loopback и частные диапазоны. |
| `MAX_POST_BYTES`, `MAX_ASSET_BYTES`, `MAX_OBJECTS` | Лимиты контента бакета. По умолчанию: 1 МиБ, 50 МиБ, 10 000. |
| `TRUSTED_PROXIES` | IP/CIDR прокси, которым можно задавать `X-Forwarded-For`. Без этого IP клиента — адрес TCP-соединения. Нужно для правильных лимитов и хеша посетителя за Caddy. |

## Развёртывание

- Сервис работает в Docker, запускается через Docker Compose.
- Образ собирает GitHub Actions и публикует в GHCR (`ghcr.io`).
- `docker-compose.yml` — для продакшена: он только скачивает выпущенный образ из GHCR, без `build:`, и закрепляет последний релиз. Локальная сборка — в `compose.dev.yml` (расширяет сервис из продакшен-файла, добавляет `build: .`, образ `hyperhack:dev`), запускается только через `docker compose -f compose.dev.yml`. Без `docker-compose.override.yml`: Compose подключает его сам, и он попал бы в продакшен.
- Compose: bind mount в подпапки (`./data`, …). Без именованных томов.
- Порт сервиса не публикуется наружу: только localhost, Docker-сеть или mesh-IP. TLS делает reverse proxy (Caddy).
- `.gitignore` пишет агент (минимум: `.env`, `data/`, результаты сборки).
- Домен: из `SITE_URL`.
- В репозитории есть `Caddyfile.example` для сервиса с доменом `example.com`: reverse proxy на сервис, `/metrics` и `/reindex` закрыты, `/assets/*` отдаётся из `vault/assets/` с заголовками и списком расширений из «Безопасность → Периметр». Тот же блок есть в README.

## Структура бакета

- `assets/` — все ассеты: обложки, картинки в постах. Решено.
- `assets/logo.svg` — необязательный логотип сайта в верхнем баре и фавиконка. Без него сервис показывает встроенный знак.
- `home.md` — необязательные блоки главной, только в корне (см. Страницы → Главная).
- Сервис игнорирует ключи, где любой сегмент пути начинается с `.` или `_` (как Remotely Save).

### Посты

- Каждый `.md` в vault — кандидат в посты, на любой глубине, кроме `assets/`, игнорируемых путей (`.` / `_`) и `home.md` в корне.
- Папки нужны только автору. На URL они не влияют.
- URL: `/posts/<slug>`. Slug берётся из frontmatter или имени файла, поэтому перенос файла не ломает ссылки.
- Нумерации нет. Порядок задаёт `date`.
- Файл без корректного frontmatter (`title` + `date`) пропускается с WARN. Шаблоны и служебные заметки — в `_templates/` или другую папку на `_`, тогда они не синхронизируются.

### Локальное зеркало vault и ассеты

- При синхронизации сервис зеркалит бакет в `VAULT_DIR` на диске: скачивает новые и изменённые объекты, удаляет исчезнувшие. Источник правды — бакет.
- Состояние зеркала (ключ объекта → `ETag`) хранится в `VAULT_DIR/.hyperhack.json`, права `0600`, поэтому после перезапуска не нужно скачивать всё заново. Удаление `vault/` запускает полную пересинхронизацию.
- Структура рядом с Compose (только bind mount, без Docker-томов):
  ```
  hyperhack/
  ├── docker-compose.yml
  ├── .env
  ├── data/    # DATA_DIR: SQLite
  └── vault/   # VAULT_DIR: зеркало бакета
  ```
- Caddy (на хосте) отдаёт `/assets/*` прямо из `vault/assets/` через `file_server`. Сервис ассеты не отдаёт.
- Caddy отдаёт только `/assets/*`. Файлы `.md` и другие пути vault наружу не видны.
- Пользователю Caddy нужно право чтения `vault/assets/`.
- Если S3 недоступен, страницы и картинки работают; новые изменения ждут следующей успешной синхронизации.
- S3 недоступен при старте: индекс строится из зеркала, сервис готов. Если зеркала ещё нет, первая синхронизация должна пройти, иначе выход с кодом 1.

Отклонено: Redis. Один экземпляр, мало постов: хватает индекса в памяти, Go map для лимитов, SQLite для счётчиков, диска и кэша ОС для файлов.

## Формат поста

Метаданные — свойства Obsidian: YAML-блок между `---` в начале файла.

```markdown
---
title: Как я ушёл с Ghost
description: Почему Ghost тяжёлый и что я написал вместо него
date: 2026-11-03
updated: 2026-11-05
tags:
  - go
  - selfhost
cover: assets/covers/ghost.webp
slug: leaving-ghost
lang: ru
draft: false
---

Текст поста…
```

| Поле | Тип | Обязательно | Назначение |
|---|---|---|---|
| `title` | строка | да | Заголовок поста. |
| `description` | строка | нет | Краткое описание: список постов, RSS, мета-теги, превью ссылки в Telegram и поисковиках. |
| `date` | дата | да | Дата публикации. Сортировка «Новые». |
| `updated` | дата | нет | Дата обновления. Показывается на посте и в RSS. |
| `tags` | список | нет | Теги. |
| `cover` | строка | нет | Путь к обложке внутри `assets/`. |
| `slug` | строка | нет | Часть URL. По умолчанию — из имени файла. |
| `lang` | строка | нет | Язык поста, ISO 639-1 (`en`, `ru`). По умолчанию — `DEFAULT_LANG`. Идёт в `<html lang>`, RSS, мета-теги. |
| `draft` | bool | нет | `true` — пост не публикуется. По умолчанию `false`. |
| `theme` | карта | нет | Цвета страницы этого поста поверх цветов сайта. См. Дизайн → Цвета → Свои цвета. |

Правила:

- `date` и `updated`: тип «дата» Obsidian (`2026-11-03`) или «дата и время» (`2026-11-03T20:59`). Парсер принимает оба.
- Нет `title` или `date`, или YAML не парсится → пост пропускается, лог WARN.
- Неверные `date`, `updated`, `slug`, `lang` (не две строчные буквы), `cover` (не разрешённый файл в `assets/`) или `draft` → пост пропускается, лог WARN.
- Slug из имени файла: строчные буквы, русские буквы транслитерируются (`ж` → `zh`, `х` → `kh`, `щ` → `shch`, `ъ` и `ь` убираются), любая другая последовательность символов → `-`. Якоря заголовков строятся так же.
- `tags`: приводятся к нижнему регистру (`Go` → `go`), дубли сливаются. Буквы любого алфавита, цифры, `-`, `_`, `/`; 1–50 символов каждый; не больше 20 на пост. Иное → пост пропускается, лог WARN.
- Два поста с одним `slug` → публикуется первый по ключу объекта, второй пропускается, лог ERROR.
- Неизвестные поля игнорируются. Obsidian может добавлять свои.
- README описывает все поля этой таблицы.

## Публикация из Obsidian

- Для блога отдельный vault. Личные заметки в бакет блога не попадают.
- Obsidian синхронизирует файлы с Garage плагином Remotely Save.
- Структура vault = структура бакета. Префикс Remotely Save остаётся пустым: у блога свой бакет.
- Шифрование Remotely Save для этого бакета выключено. Иначе сервис не прочитает файлы.
- Remotely Save не синхронизирует файлы и папки, имя которых начинается с `.` или `_`.
- Remotely Save не вызывает `/reindex`. Новый пост появляется после ближайшего опроса.

### Настройки Obsidian («Файлы и ссылки»)

| Настройка | Значение |
|---|---|
| Использовать [[Wiki-ссылки]] | выкл. |
| Формат новой ссылки | абсолютный путь от корня хранилища |
| Место для вложенных файлов по умолчанию | папка, указанная ниже → `assets` |

С этими настройками картинка вставляется как стандартный Markdown: `![](assets/abstract-5.jpg)`.
Рендер поддерживает только стандартные Markdown-ссылки. Wikilinks (`![[…]]`) не поддерживаются.
Путь `assets/…` в посте ведёт на `/assets/…` сайта.
README описывает эти настройки.

Предложено: если в посте есть `![[`, лог WARN — так автор заметит неверную ссылку.

## Синхронизация контента

Garage не шлёт уведомления об изменениях в бакете (нет S3 event API).
Сервис узнаёт об изменениях двумя способами:

1. **Опрос.** Каждые `POLL_INTERVAL` (30–60 с) — `ListObjectsV2` по бакету.
   Сравнить `ETag` каждого объекта с кэшем.
   Скачать и перерендерить только новые и изменённые объекты.
   Удалить посты, объектов которых больше нет.
2. **Ручной запуск.** `POST /reindex` с токеном.
   Вызывается через приватную сеть (на публичном домене закрыт), и пост появляется сразу.

Опрос — запасной путь. Эндпоинт — быстрый путь.

- Ошибки S3: до 3 попыток за опрос (повтор через 5 с, затем через 30 с), WARN на каждую неудачную попытку, ERROR после последней.
- Если скачать объект не удалось, остаётся старая копия; следующий опрос пробует снова.
- `POST /reindex` ждёт окончания синхронизации: `204` готово, `401` неверный токен, `403` адрес не в `REINDEX_ALLOW`, `503` синхронизация не удалась.

## Метрики постов

Общий трафик уже есть в логах reverse proxy и Grafana. Сервис его не дублирует.
Сервис хранит только метрики постов. Хранилище: SQLite.

### Просмотры

- Считает клиентский скрипт, не рендер страницы. Тот же скрипт шлёт время на странице.
- Клиенты без JS (почти все боты) не считаются. Читатели с выключенным JS тоже. Принято.
- Публично: показывается на посте.
- Источник для списка «Популярные».
- Повторные просмотры одного посетителя не считаются: суточный хеш посетителя (см. «Безопасность → Голоса и идентификация посетителя»); сырой IP не хранится.

### Время на странице

- Сервер сам его не измерит. Нужен клиентский скрипт.
- Скрипт шлёт активное время чтения, когда страницу скрывают или закрывают (`visibilitychange` / `pagehide`, `fetch` с `keepalive`).
- Считается только время, когда вкладка видима.
- В каждой дельте — случайный id просмотра страницы. Сервер суммирует дельты просмотра и ограничивает сумму 4 ч, затем добавляет её в агрегат поста: среднее время = сумма секунд / просмотры со временем чтения.
- Не публично. На сайте не показывается. Только метрика (см. «Мониторинг»).

### Расчётное время чтения

- Публично: показывается на посте (например, «5 мин чтения»).
- Считается из текста поста при рендере: число слов / `READING_WPM`, с округлением вверх, минимум 1 минута.
- Предложено: блоки кода и картинки учитываются отдельно.
- Не связано с измеренным временем на странице.

### Лайки и дизлайки

- Анонимно. Без аккаунта.
- Один голос на cookie `vid` на пост (см. «Безопасность → Голоса и личность посетителя»). Голос можно сменить или снять.
- Счётчики публичны на посте.
- Каждый голос проходит проверку ALTCHA (см. «Безопасность → ALTCHA»).

## Функции контента

### Подсветка кода

- На сервере при рендере: `github.com/yuin/goldmark` + `github.com/yuin/goldmark-highlighting/v2` (chroma v2). Без JS.
- CSS-классы, не inline-стили (`chromahtml.WithClasses`), чтобы у светлой и тёмной темы была своя палитра.
- Шапка 44px над каждым блоком, в том числе с отступом: язык слева цветом `--muted` (пусто, если не задан), кнопка «Копировать» справа. После клика галочка и «Скопировано» на 1.5 с. Кнопка появляется только с JS. Язык — это атрибут, его показывает CSS, поэтому он не попадает в текст для поиска и в RSS.

### Callout

- Синтаксис Obsidian: `> [!note]`, `> [!tip]`, `> [!warning]`, без учёта регистра, с необязательным заголовком после типа. Разбирает рендер. Любой другой тип остаётся обычной цитатой.
- Блок на `--uv-soft`, радиус 14px, иконка и заголовок типа, без цветной полосы слева. Иконки из CSS.
- Заголовки по умолчанию идут по `lang` поста, потому что HTML поста рендерится один раз: русский для `ru`, иначе английский.

### Формулы

- Синтаксис Obsidian: `$…$` в строке, `$$…$$` отдельным блоком (на своих строках или в одной). Как в Obsidian, после открывающего `$` нет пробела, а перед закрывающим нет пробела и после него нет цифры, поэтому `$5 and $10` остаётся текстом. `\$` — обычный знак доллара. Код в строке и блоки кода не разбираются.
- На сервере: TeX → MathML через `github.com/wyatt915/treeblood` `v0.1.16` (чистый Go, MIT). Браузеры показывают MathML сами: без JS, без изменений CSP, формулы работают и в RSS.
- Формула длиннее 4096 байт или такая, которую конвертер не принял, показывается своим TeX в `<code class="math-error">`.
- MathML проходит `bluemonday` по белому списку: элементы представления и простые атрибуты со строгими значениями; без `style`, `href`, `annotation-xml`, `mglyph` и `maction`. Исходный TeX остаётся в `<annotation>`; в текст для поиска идёт TeX, а не MathML.
- Широкая блочная формула прокручивается вбок внутри своего блока.

### Диаграммы

- Синтаксис Obsidian: блок кода ` ```mermaid `. Рисуется в браузере библиотекой Pele (Mermaid → SVG, MIT), лежит в репозитории как `static/pele.js` (1.13.0, `dist/pele.global.js` сверен с integrity-хешем npm, лицензия в `static/pele-LICENSE.txt`).
- `pele.js` и `diagram.js` загружаются только на постах с блоком ` ```mermaid `. Без JS, в RSS и при ошибке в диаграмме остаётся блок кода.
- Pele пишет атрибуты `style="…"`, которые блокирует CSP. `diagram.js` переименовывает их до разбора и ставит те же стили через CSSOM, который CSP разрешает. Масштабирование Pele выключено: его кнопки ставят атрибуты style.
- Рамка как у блока кода; цвета из токенов темы через переменные `--pele-*`. Раскладка подстраивается под ширину колонки.

### Поиск

Цель: лучший поиск, какой возможен без отдельного сервиса.

- Встроенный полнотекстовый индекс: Bleve v2 (`github.com/blevesearch/bleve/v2`), в памяти, перестраивается при синхронизации.
- Анализ по языку поста (`lang`): английский и русский анализаторы (русский: стеммер Snowball + стоп-слова, пакет `analysis/lang/ru`). «Постов» находит «пост».
- Поля и вес: `title` > `tags` > `description` > текст.
- Устойчивость к опечаткам (fuzzy), поиск по префиксу для поиска при наборе.
- Сниппеты с подсветкой совпадений.
- Работает без JS: `GET /search?q=…` рендерит результаты.
- С JS: `Ctrl K`, `Cmd K` и `/` открывают палитру, `<dialog>` 660px по центру, отступ сверху 110px, с затемнением фона. Результаты обновляются при наборе, из `/search`.
- Фильтр по тегу прямо в запросе: `#self-host garage`. Сервер берёт токены `#тег` из `q` и фильтрует по ним, несколько тегов — И. Запрос только из тегов выводит их посты по дате. Токен с неверным синтаксисом тега игнорируется. Параметр `tag` остаётся для старых ссылок: он становится токеном `#тег` в запросе. В форме поиска нет выпадающего списка тегов.
- Пока вводится токен с `#`, палитра вместо результатов показывает подсказки тегов с числом постов. Подсказки подбираются по началу тега, сначала самые частые. Клик или `Enter` дописывает тег и пробел. Выбранные теги показаны чипами под полем.
- Теги с числом постов приходят как `<script type="application/json">` в странице; нового эндпоинта нет.
- Подвал палитры: `#тег` — фильтр по тегу, `↑ ↓` — выбрать, `Enter` — открыть, `Esc` — закрыть. Первый результат выбран сразу; за любым концом списка ничего не выбрано, и тогда `Enter` открывает страницу результатов.
- Совпадение в заголовке подчёркнуто и окрашено `--uv`; в выбранной строке цветом `--text`. Слишком длинный для подсветки заголовок остаётся без неё.
- Нет результатов: «Ничего не нашлось по «…». Проверь слово или убери #тег из запроса.»
- У страницы результатов `noindex`.

Отклонено: Meilisearch и подобные. Опечатки ловит лучше, но это отдельный сервис.

### Популярные и новые

- «Популярные»: больше всего просмотров за последние `POPULAR_DAYS` дней, топ `limit` блока `popular`.
- «Новые»: по `date`, блок `posts`, с пагинацией.

### Теги

- Страница `/tags/<tag>`: посты с этим тегом, с пагинацией.
- Страницы тегов используют те же строки постов, что и блок `posts`.
- Все теги выглядят одинаково: `#` цветом `--uv`, затем имя. Своих цветов у тегов нет.

### RSS

- RSS 2.0 на `/rss.xml`, последние `RSS_LIMIT` постов.
- Полный HTML поста в `content:encoded`, `description` как краткое описание. Все URL абсолютные.
- `<link rel="alternate">` для автообнаружения на каждой странице.

### SEO и находимость

- Серверный семантический HTML. Быстрые страницы: без блокирующего JS, `width`/`height` у картинок, `loading="lazy"`, `alt` из Markdown.
- `<title>`, meta description из `description`, canonical URL из `SITE_URL`, `<html lang>` из `lang` поста.
- Open Graph и Twitter Card (`summary_large_image`): картинка из `cover`, иначе `DEFAULT_OG_IMAGE`.
- JSON-LD `BlogPosting`: заголовок, даты, автор, картинка, язык, ключевые слова.
- `sitemap.xml` с `lastmod` из `updated` или `date`.
- `robots.txt`: разрешить всех краулеров, включая ИИ-краулеров; ссылка на sitemap.
- Исходный Markdown для агентов: `/posts/<slug>.md`.
- Пинг IndexNow при новом или изменённом посте, если задан `INDEXNOW_KEY` (Bing, Яндекс; Google IndexNow не использует).
- `/llms.txt`: генерируется, потому что это дёшево. Реально ИИ-ассистенты его сейчас почти не читают.
- Настоящий статус `404` для отсутствующих страниц.

### Healthcheck

- `GET /healthz`: `200`, когда индекс загружен, иначе `503`.
- В образе нет curl, поэтому у бинарника есть подкоманда `healthcheck` для healthcheck в Compose.

### Дополнительные метрики поста

Все не публичные: только метрики, на сайте не показываются. Собирает тот же клиентский скрипт и сервер. Без трекинговых cookie, без фингерпринтинга сверх суточного хеша посетителя.

| Метрика | Источник | Зачем |
|---|---|---|
| Просмотры по дням по посту | скрипт | Тренды; основа «Популярных». |
| Глубина чтения: доля читателей, дошедших до 25 / 50 / 75 / 100 % текста | скрипт (`IntersectionObserver` на метках) | Дочитывают ли пост. |
| Источник трафика по посту: `telegram`, `google`, `yandex`, `bing`, `github`, `direct`, `internal` (с этого сайта), `other` | скрипт (домен `document.referrer`, сведённый к фиксированному списку) | Откуда приходят читатели. |
| Клики по внешним ссылкам по посту (домен цели) | скрипт | Какими ссылками пользуются. |
| Копирования кода по посту | скрипт (событие `copy` внутри блоков кода, кнопка «Копировать») | Какой код полезен. |
| Класс устройства: `mobile` / `tablet` / `desktop` | скрипт (диапазон ширины viewport) | Приоритеты вёрстки. |
| Выбранные язык интерфейса и тема | скрипт | Какие язык и тему выбирают. |
| Голоса по дням по посту | сервер | Тренды голосов. |
| Поиск: число запросов, число запросов без результатов, топ запросов, топ запросов без результатов | сервер | Что ищут и не находят. |

Правила:

- Значения меток Prometheus ограничены: slug поста, фиксированный список источников, фиксированный список устройств. Никогда не делать метками сырые URL, рефереры и запросы.
- Поисковые запросы хранятся в SQLite (нормализованные, в нижнем регистре). `/metrics` отдаёт только топ `N` как gauge, обновляется периодически.
- Скрипт шлёт один beacon-запрос при каждом скрытии (`visibilitychange` / `pagehide`) с тем, что изменилось с прошлой отправки, и с id просмотра страницы. Просмотр считается один раз. Лимит — `RATE_LIMIT_BEACON`.

## Мониторинг

- Сервис отдаёт формат Prometheus на `/metrics`, на основном порту.
- Reverse proxy закрывает `/metrics` на публичном домене.
- VictoriaMetrics собирает метрики напрямую с сервиса, мимо proxy. Prometheus-сервера нет.
- Дашборд Grafana (JSON) лежит в репозитории: `grafana/hyperhack.json`.
- Метрики: все метрики постов (см. «Метрики постов»); статус синхронизации (последний опрос, ошибки, число объектов); время поиска; HTTP-запросы, ошибки, задержки.

## Логирование

- Библиотека: `log/slog` из стандартной библиотеки Go.
- Уровни: `DEBUG`, `INFO`, `WARN`, `ERROR`. Задаётся `LOG_LEVEL`.
- Формат: JSON в stdout (для Docker и Loki). Текстовый — для локальной разработки. Задаётся `LOG_FORMAT`.
- Поля каждой записи: `time`, `level`, `msg`, `component` (`main`, `sync`, `http`, `render`, `votes`, `metrics`, `store`). `main`: запуск, конфиг и остановка.
- HTTP-записи: `request_id`, метод, путь, статус, длительность.
- Ошибка при старте (конфиг, SQLite; S3 только если локального зеркала ещё нет) → лог `ERROR` и выход с кодом 1.

| Уровень | Что пишется |
|---|---|
| `DEBUG` | Детали синхронизации (каждый объект, сравнение `ETag`), рендер поста, запросы к SQLite, каждый HTTP-запрос. |
| `INFO` | Старт и сводка конфига (без секретов), итог опроса (добавлено / обновлено / удалено), вызов `/reindex`, остановка. |
| `WARN` | Пост пропущен (нет `title` или `date`, битый YAML), сработал лимит запросов, ALTCHA не прошла, временная ошибка S3 с повтором. |
| `ERROR` | Конфликт `slug`, S3 недоступен после повторов, ошибка записи в SQLite, перехваченная паника в обработчике. |

Никогда не логировать: токен `/reindex`, ключи S3, секрет ALTCHA, сырой IP, хеш посетителя.

Предложено: каждый HTTP-запрос только на `DEBUG`. Журнал запросов уже пишет reverse proxy.

## Безопасность

### Модель угроз

| Что защищаем | Угроза | Главная мера |
|---|---|---|
| Страницы и читатели | XSS, подмена контента, clickjacking | Экранирование, санитайзер, строгий CSP, заголовки безопасности |
| Голоса и просмотры | Боты, накрутка, CSRF | ALTCHA, лимиты, cookie голоса, проверка Origin |
| Хост и сервис | DoS, исчерпание ресурсов, выход из контейнера | Лимиты, таймауты, защищённый контейнер |
| Контент бакета | Взломанное устройство автора пишет плохие файлы | Ключие, лимиты размеров, санитайзер, проверка путей |
| Секреты | Утечка через репозиторий, логи, образ | Только `.env`, никогда не логируются, secret scanning |
| Цепочка поставок | Вредная зависимость или action, подмена образа | Закреплённые actions, Dependabot, `govulncheck`, attestations |
| Приватность читателей | Слежка, утечки IP | Без сырого IP, суточный HMAC-хеш, без сторонних запросов |

Границы доверия: интернет → Caddy → сервис; бакет → сервис (доверие частичное: пишет только автор, но его устройства могут взломать); CI → GHCR → хост.

### Периметр (Caddy, вне сервиса)

- `caddy-ratelimit` + CrowdSec bouncer. Лимит: 1200 запросов в минуту на IP клиента; `/static/*` и `/assets/*` не учитываются.
- На публичном домене закрыт `/metrics`, `/reindex`.
- `/assets/*`:
  - Разрешённые расширения: `png jpg jpeg webp avif gif svg mp4 webm`. Остальное → `404`.
  - Заголовки: `X-Content-Type-Options: nosniff` и `Content-Security-Policy: default-src 'none'; img-src 'self'; style-src 'unsafe-inline'; sandbox`. SVG со скриптом не выполнится.
- Лимит тела запроса для `/api/*`: 16 КБ.
- `Strict-Transport-Security: max-age=31536000` (без `includeSubDomains` и без preload по умолчанию).
- Заголовок `Server` убран.
- Без Cloudflare: его замедляют в России с июня 2025, а большинство читателей в России. Защиты от DDoS выше по сети нет: риск принят.
- Отклонено: проверка при входе на сайт (например, Anubis). Она может блокировать поисковики и ботов превью ссылок.

### Эндпоинты

| Эндпоинт | Метод | Доступ | Защита |
|---|---|---|---|
| Страницы, `/search`, `/tags/*`, `/rss.xml`, `/sitemap.xml`, `/robots.txt`, `/llms.txt`, `/posts/<slug>.md` | GET | публичный | `RATE_LIMIT_SEARCH` на `/search` |
| `/api/altcha` | GET | публичный | `RATE_LIMIT_VOTE` |
| `/api/vote` | POST | публичный | ALTCHA, cookie голоса, `RATE_LIMIT_VOTE`, проверка Origin |
| `/api/beacon` | POST | публичный | `RATE_LIMIT_BEACON`, проверка Origin, строгая схема |
| `/reindex` | POST | приватная сеть | блок в Caddy, `REINDEX_ALLOW`, `REINDEX_TOKEN` |
| `/metrics` | GET | приватная сеть | блок в Caddy, `METRICS_ALLOW` |
| `/healthz` | GET | публичный | постоянный ответ, без данных |
| `/prefs` | POST | публичный | тело формы ≤ 4 КБ, проверка перечислений `theme` / `lang`, редирект только на локальный путь |
| `/favicon.ico` | GET | публичный | встроенный знак в SVG или `302` на `/assets/logo.svg`, если в бакете есть логотип; никогда не `404` |
| `/static/*` | GET | публичный | встроенные CSS, JS и шрифты, а также `/static/theme/<hash>.css` из проверенных цветов (неизвестный хеш → `404`); без листинга папок |

Другие методы → `405`. Неизвестные пути → `404`.

### Проверка входных данных

- Размер тела: `http.MaxBytesReader`, 4 КБ для `/api/*`.
- JSON: обязателен `Content-Type: application/json`, `DisallowUnknownFields`, только один объект.
- Slug должен быть в текущем индексе. Неизвестный slug → `404`, ничего не сохраняется. Это же ограничивает метки метрик.
- Числа ограничены: время на странице 0–4 ч; глубина чтения только 0 / 25 / 50 / 75 / 100.
- Только перечисления: голос (`like` / `dislike` / `none`), источник, устройство, тема, язык. Другие значения → `400`.
- Поисковый запрос: максимум 200 символов, максимум 10 слов, включая токены `#тег`. Запрос строится в коде (match + fuzzy + prefix), никогда не из синтаксиса query-string Bleve: это закрывает DoS через regex и wildcard. Опечатки ≤ 2, префикс от 2 символов. Номер страницы ограничен.
- Cookie `lang` и `theme`: проверка по перечислению; неверное значение → по умолчанию.
- Цвета темы из `home.md` и постов: только известные имена, только hex-цвета. Всё остальное игнорируется.

### Вывод и XSS

- Весь HTML через `html/template` (экранирование по контексту). Шаблоны парсятся при старте.
- Markdown: goldmark с GFM (таблицы, зачёркивание, автоссылки), без `WithUnsafe`. По умолчанию goldmark не рендерит сырой HTML и опасные URL.
- Второй слой: HTML поста проходит `bluemonday` (политика UGC + классы chroma + id заголовков + классы callout и блоков кода + атрибут языка кода + белый список MathML).
- Внешние ссылки получают `rel="noopener noreferrer"`.
- Картинки только из `assets/`. Внешние картинки блокирует CSP (заодно IP читателей не уходят наружу).
- JSON-LD через `json.Marshal` (экранирует `<`, `>`, `&`).
- RSS и sitemap через `encoding/xml`.
- `/posts/<slug>.md`: `Content-Type: text/markdown; charset=utf-8`, `nosniff`.
- Страницы ошибок не показывают внутренние детали.

### Заголовки безопасности (ставит сервис)

- `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests`. `blob:` в `worker-src` добавлять, только если этого требует сборка ALTCHA.
- Нет inline-скриптов и inline-стилей. Тема и язык берутся из cookie и рендерятся на сервере, поэтому inline-скрипт против мигания темы не нужен. `<script type="application/json">` — блок данных, который не выполняется, поэтому CSP не меняется.
- `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Cross-Origin-Opener-Policy: same-origin`, `X-Frame-Options: DENY`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), browsing-topics=()`.
- Все JS, CSS, шрифты и решатель ALTCHA лежат на своём сервере. Без CDN, без сторонних запросов.

### CSRF и CORS

- Заголовков CORS нет.
- `/api/*` требует `Content-Type: application/json` (форма с другого сайта не отправит его без preflight) и same-origin `Origin` / `Sec-Fetch-Site`.

### Голоса и личность посетителя

- Личность для голоса: анонимная случайная cookie `vid` (128 бит, `HttpOnly; Secure; SameSite=Lax; Max-Age=1 год`). Личных данных в ней нет.
- Один голос на `vid` на пост. Если удалить cookie, можно проголосовать снова, но каждый голос стоит решения ALTCHA и упирается в `RATE_LIMIT_VOTE`.
- Почему не хеш IP: многие читатели делятдин IP (мобильный CGNAT), а суточный хеш разрешил бы голос раз в день.
- Дедупликация просмотров: `HMAC-SHA256(daily_key, ip_prefix + user_agent)`, `daily_key = HMAC(VISITOR_SECRET, date)`. `ip_prefix`: адрес IPv4 или `/64` IPv6. Хеши текущего дня живут только в памяти; старые суточные ключи не хранятся, поэтому дни нельзя связать. Сырые IP никогда не хранятся и не логируются.

### ALTCHA

- Библиотека: `github.com/altcha-org/altcha-lib-go/v2` (задачи v2). Невидимо: скрипт поста решает задачу при клике своим маленьким решателем (`static/altcha.js`), без виджета.
- `ALTCHA_HMAC_KEY` ≥ 32 случайных байт.
- Срок жизни задачи `ALTCHA_EXPIRES` (по умолчанию 5 мин). Истекла → отказ.
- Защита от повтора в сервисе: использованные задачи хранятся в памяти до истечения; повтор → отказ. Библиотека этого не делает.
- Сложность: `ALTCHA_MAX_NUMBER`.

### Лимиты запросов (сервис)

- Ключ: IP клиента через `TRUSTED_PROXIES`; IPv6 группируется по `/64`.
- Token bucket в памяти с жёстким потолком числа клиентов (старые вытесняются), поэтому поток IP не съест RAM.
- Лимиты: `RATE_LIMIT_VOTE`, `RATE_LIMIT_BEACON`, `RATE_LIMIT_SEARCH`, `RATE_LIMIT_REINDEX`. Превышение → `429` + `Retry-After`, лог WARN.

### Приватные эндпоинты

- `/metrics` и `/reindex`: закрыты в Caddy и принимаются только с CIDR из `METRICS_ALLOW` / `REINDEX_ALLOW` (по умолчанию: loopback и частные диапазоны). Два независимых слоя.
- `REINDEX_TOKEN` ≥ 32 байт, передаётся как `Authorization: Bearer`, сравнивается через `crypto/subtle.ConstantTimeCompare`.
- Одновременно идёт только одна переиндексация. Лишние вызовы ждут текущую.

### Бакет и локальное зеркало

- У сервиса свой ключ Garage только с правом **read**. Remotely Save использует отдельный ключ с read + write.
- S3 по HTTPS с проверкой сертификата.
- Лимиты размеров: `MAX_POST_BYTES` (по умолчанию 1 МиБ), `MAX_ASSET_BYTES` (50 МиБ), `MAX_OBJECTS` (10 000). Превышение → пропуск + WARN. `MAX_OBJECTS` считает все ключи бакета, включая игнорируемые.
- Запись в зеркало через `os.Root` (Go ≥ 1.24): выйти через `..` или symlink нельзя. Ключи с абсолютным путём, `\`, NUL или управляющими символами отклоняются.
- Ассеты: тот же список расширений, что в Caddy.
- Атомарная запись (временный файл + rename), поэтому Caddy не отдаст недописанный файл.
- Права: папки `0755`, файлы `0644` (Caddy нужно чтение). Файл SQLite `0600`.
- Размер frontmatter проверяется до парсинга YAML. `cover` должен указывать внутрь `assets/`.
- Slug: `^[a-z0-9-]{1,100}$`. Имя файла с другими символами (например, кириллицей) транслитерируется. Если результат пустой и `slug` нет → пропуск + WARN.

### HTTP-сервер

- `ReadHeaderTimeout` 5 с, `ReadTimeout` 10 с, `WriteTimeout` 30 с, `IdleTimeout` 120 с, `MaxHeaderBytes` 16 КБ.
- Таймауты через context на вызовы S3.
- Middleware восстановления после паники → `500` + лог ERROR.
- Плавная остановка по SIGTERM.
- Без pprof и отладочных эндпоинтов в релизных сборках.

### Данные

- SQLite: только парамеросы; WAL; `busy_timeout`.
- Ограниченный рост: агрегаты по дням, не сырые события; таблица поисковых запросов с потолком и TTL.
- `data/` бэкапит хост (вне сервиса).

### Контейнер

- Статический бинарник (`CGO_ENABLED=0`, `-trimpath`), драйвер SQLite на чистом Go `modernc.org/sqlite`.
- Образ: distroless static non-root или `scratch`. Без shell и пакетного менеджера.
- Пример Compose:
  ```yaml
  services:
    hyperhack:
      image: ghcr.io/<owner>/hyperhack:<version>
      user: "10001:10001"
      read_only: true

      security_opt: [no-new-privileges:true]
      tmpfs: [/tmp]
  ```

### Секреты

- Только в `.env`. В `.env.example` — заглушки.
- Проверка при старте: обязательные секреты есть и достаточно длинные, иначе выход с кодом 1.
- Никогда не логируются, не попадают в сообщения об ошибках и в образ.
- README описывает ротацию: `REINDEX_TOKEN`, `ALTCHA_HMAC_KEY`, `VISITOR_SECRET`, ключи S3.

### Цепочка поставок и CI

- GitHub Actions закреплены по полному SHA коммита.
- Минимальные `permissions:` на job: по умолчанию `contents: read`; `packages: write`, `id-token: write`, `attestations: write` — только в release job.
- Без `pull_request_target` с checkout кода PR. PR из форков не получают секретов.
- Dependabot: `gomod`, `github-actions`, `docker`.
- Проверки в CI: `go vet`, `staticcheck`, `govulncheck`, тесты с `-race`, CodeQL (Go).
- Релиз: сборка образа, push в GHCR, attestation через `actions/attest` (`push-to-registry: true`). Проверка на хосте: `gh attestation verify oci://ghcr.io/<owner>/hyperhack:<version> -R <owner>/hyperhack`.
- Теги образа: semver без `v` (git-тег `v0.1.0` → образ `0.1.0`), никогда не перезаписываются. В Compose закреплена версия, не `latest`. После релиза отдельный PR переводит тег в `docker-compose.yml` на новую версию.
- Настройки репозитория: защита ветки `main` (обязательны PR и проверки, без force push), secret scanning + push protection, private vulnerability reporting. `SECURITY.md` объясняет, как сообщить об уязвимости.

### Тесты безопасности

- Набор XSS-нагрузок через конвейер Markdown → HTML.
